## PART F — Performance: fix the slow navbar & heavy animations

### F1. Throttle + passivize the scroll listener (all 22 pages)
Every page runs an un-throttled, non-passive scroll listener that toggles `.scrolled` on the navbar — fires 60×/sec. Fix on every page:
```js
let ticking = false;
const navbar = document.getElementById('navbar'); // cache once (index.html re-queries each event today)
window.addEventListener('scroll', () => {
  if (!ticking) {
    requestAnimationFrame(() => { navbar.classList.toggle('scrolled', window.scrollY > 10); ticking = false; });
    ticking = true;
  }
}, { passive: true });
```

### F2. De-blur the navbar (all 22 pages)
`backdrop-filter: blur(16px)` is the single most expensive CSS property — repaints on every scroll. Replace with a solid translucent background (`rgba(250,249,246,0.96)`) that achieves the same visual. Only add `backdrop-filter` as a progressive-enhancement layer, OR drop it entirely. This is the biggest scroll-jank fix.

### F3. Stop the `transition: all` on navbar (all 22 pages)
`transition: var(--transition)` = `all 0.25s` on a blurred element re-evaluates every property. Replace with `transition: box-shadow 0.25s ease` (the only thing `.scrolled` actually changes).

### F4. Stabilize the dispatch map (index.html)
You said it feels "unstable / a little high speed." Reduce the simultaneous animations from 14 → a calmer set:
- Slow hub pulse (2.6s → 3.5s), stagger them more.

- Remove the 2 `<animateMotion>` moving courier dots (these are the jittery part) OR slow them dramatically and reduce to 1.
